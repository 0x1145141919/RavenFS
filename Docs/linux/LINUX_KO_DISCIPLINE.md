## 0. 三层约束（本子项目宪法）

用户口径（原文）：

> *"能用内核成熟框架就用内核成熟框架，在满足以 archlinux 一大堆用户态程序的规格需求第一约束下的第二约束，目的是尽可能减少 ai 的对于不良定义问题的暴露面。"*

**约束三层，逐层服从上一层**：

```
第一约束（正确性）  ：满足 Arch Linux 用户态程序的规格需求。         ← 目标层，优先
第二约束（框架优先）：能用内核成熟框架/惯例就用，作为默认选项——      ← 手段层
                      哪怕不是最优、哪怕多绕一层。
第三约束（用户暴露）：前两层之下，凡撞上"非良定义问题"，第一时间     ← 纪律层
                      上报用户——那是用户的学习面，也是风险；
                      接受进度慢，不接受隐患。
```

- **第一约束** = 满足 Arch Linux 用户态程序的规格需求（原由 linux-ko 需求规格书以 R-* 编号实体化；该规格书已随工作文档退役，此处仅留原则）。
- **第二约束**判「怎么实现」；**第三约束**判「遇到说不清的事怎么办」。

---

## 1. 第二约束的可操作形式（只判"怎么实现"，按顺序过）

| 顺位 | 动作 | 判定 |
|---|---|---|
| 1 | **照抄内核成熟框架/惯例** | 默认选项，哪怕不是最优、哪怕要多绕一层 |
| 2 | **降级功能**（`-EOPNOTSUPP`） | 框架不覆盖且非 Arch 必需时 |
| 3 | **拒绝发明** | 禁止自创语义弥补；宁可缺功能 |
| 4 | **必须自创** | 写进契约 + 配检查项 + 写明"为什么框架不行"（对齐 `../DISCIPLINE.md`）；**并触发第三约束（上报用户）** |

---

## 2. 第三约束的触发面

任何"**非良定义问题**"——规范没说清 / 框架没覆盖 / 行为无从对照——都是风险，**不得自行拍脑袋消化**，一律第一时间上报用户。**进度可以慢，隐患不可以留。**

---

## 3. 第三约束附加指导：小步快跑（2026-09-27 定）

1. **每步必须小且可验收**：一个能独立**编译 + 实测**（guest 挂载 / `audit_v1.2` / 对照）的增量才算"一步"。**只写了机构、没接线、跑不了 = 未完成**。
2. **一步一提交**：commit message 写给**接手者**——本步做了什么 / 定下的契约与决策 / 踩的坑 / 下一步；不靠会话记忆。
3. **不憋大招**：宁可多切几个可测小步，也不要一次性大跳跃。大跳跃 → **错误放大**（前车之鉴：2026-09-26「错误注释幻觉」——一条错误注释被采信后跨文件传播，见 memory/2026-09-26）。
4. **错了立刻回退，连根铲除**：发现前提错误（含文档/代码注释）先停下澄清、全仓铲除再继续；不为已投入的工作辩护。
5. **每步收尾落文档**：规格 / 契约 / 坑写进对应 Docs（spec / handover / 移植 notes），**不留在会话里**。
6. **量力而上报**：一步的规模超出"小"（如 M5 提前做）时，先向用户报清规模与依赖，再动手。

---

## 4. 三条边界（总则管不到，显式豁免）

1. **磁盘布局必须自创** → 风险只能靠 **不变量 + `audit_v1.2`** 兜（v1.2 §7 不变量 / spec）。
2. **性能不达标允许退回自创**，但要有退出条件：先框架 → 基准证明不足 → 才自创，且书面论证。
3. **第一约束必须先变成可勾选清单**（可签发 / 可验收的需求条目），否则退化成口号。

---

## 5. 代价要写成决定

会主动放弃的东西——**缓存控权**（E1：缓存/IO 全下沉 Linux）、B+tree 某些激进度——"放弃"必须落成**决定**（写进 spec / handover），不能留"以后再说"。

---

## 6. 红线（本子项目）

- **宿主 `sudo` 不给**；**不用录存口令提权**（例外：guest 测试 VM 凭证，用户已授权）。
- **宿主/guest 内核版本不同 ⇒ 永远 guest 内编译再测**；宿主 ko 不 `insmod`。
- **成本审计**：下载 / 大流量 / 长耗时先量化，价值 < 成本就停（`COST-AUDIT-DISCIPLINE.md`）。
- 用户风格：直接、要**思维可见**（设计意图 / 推理外显）、讨厌废话；**不良定义点主动上报**。
