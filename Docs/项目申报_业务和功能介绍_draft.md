## 一、立项背景和目标

RavenFS 是自研的 B+tree 块级文件系统，非照规格书设计，而是**自然成长于一片特定的设计空气**：单用户、富内存、NVMe SSD、盘少工况好、CPU 核心多并发上限高。设计高度讨好 happy path：元数据走内存分片缓存、分配器按 CPU 分片，以富余换简洁与吞吐。代价诚实说明：初版设计时作者是新手，未引入日志等容灾技术，容错存在系统性忽视——定位实验性 FS，勿承载真实数据。目标：学习用尽可能简洁的设计满足高并发，并把"能跑"推进到"可部署、可维护"。ravendsrv 用户态服务器企划已被否决，仅保证 Linux ko 挂载运行，远期移植自研 SparrowOS。

## 二、软件功能、核心功能模块

**总纲**：全模块以统一磁盘布局契约（SB/位图/inode 面/B+tree）为最大公约数——契约唯一、实现独立、互不链接，杜绝共因失效。

**三个同量级独立模块**：

1. **上帝类** — 用户态 C++ 全功能原型，所有算法核心思想的验证场：B+tree、按 CPU 分片的块分配器、分片元数据缓存、direct/extent 双形态 inode 均先在此跑通，是生态算法母本；
2. **ravenfs.ko** — 基于上帝类逐模块移植（I/O 层换 bio/私有 buffer cache），pacman+DKMS 交付，内核升级自动重编；
3. **audit** — 顶替 fsck 生态位。不做 fsck：fsck 是不良定义问题，遇足够多真实故障前写不出，也无长期场景；audit 逐一断言盘上契约不变量，带 trace 档位呈现数据块分布，作行为调优凭据。刻意不链接核心库，避免继承上帝类 bug。

**构建与运维小工具**（不同量级）：**mkfs.ravenfs**（格式化，兼容双布局）；**sbinfo**（SB 只读查看器，类 dumpe2fs，秒开）。

**用户态离线维护工具**（基于上帝类二次开发）：**rfs_compact**（碎片压实，extent 收敛整域并降级 direct）；**rfs_freeruns / rfs_slice_fr**（空闲区间与分片视图 dump，回收决策凭据）；**rfs_cachectl**（元数据缓存在线控制）。

## 三、业务流程、功能路径

**生命周期主线**：mkfs 格式化 → ko 挂载 → rfs_cachectl 调优 → sbinfo/rfs_freeruns 巡检 → rfs_compact dry-run 报告、apply 压实 → audit 全盘校验（+trace 看数据块分布）。

**排障路径**：SB 层找 sbinfo；SB 之下找 audit；空间/碎片依次用 rfs_freeruns、rfs_slice_fr、rfs_compact 分级修复。

**开发迁移路径**：算法先在上帝类（用户态原型+测试）验证 → 换 I/O 层移植进 ko → DKMS 打包 → QEMU 压测 + 实体机灰测后交付。
