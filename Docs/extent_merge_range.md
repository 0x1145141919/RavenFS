## 1. 定位

```cpp
result_code_t extent_merge_range(uint64_t &root_blk, uint64_t owner_inode_idx,
                                 uint64_t logical_block_interval_base, uint64_t blk_len);
```

**区间融合原语**：给定逻辑块域 `I = [logical_block_interval_base, +blk_len)`（左闭右开），
把树中满足"逻辑紧贴 + 物理连续"的相邻 extent 记录对融合成一条——直到 I 内无可融合对。
注释原文要点：

- 纯**记录层**操作：不关心外部位图实际占用，只是记录耦合——融合不分配/不释放任何
  数据块，物理块集合不变（两条记录并一条：`前.length += 后.length`，删后记录）；
- detach 契约延续：`root_blk` in/out（融合链能触发根收缩，新根经引用带出）、
  `owner_inode_idx` 纯审计锚（根 meta "."，零 inode I/O）、不做顶层 inode 态校验。

### 1.1 与 map_range 自动合并的关系（为什么需要它）

`extent_map_range` 插入时已做左并/右并（逻辑紧贴 && phys 连续自动吞并，含跨界右并），
正常管线产出的树**不存在**可并残留（审计 canonical 检查保证）。但 map 的合并只在
**插入瞬间**生效，管不了历史遗留。merge_range 是**显式收敛工具**，用武之地：

1. **extent→direct 坍缩前置**（终态机第 7 条 / 待办 #3 关联）：坍缩要求全文件 =
   单条覆盖 `[0, size)` 的 extent；对全域调一次 merge，收敛到单条即坍缩可行；
2. **fsck 修复**：扫描发现 canonical 违规（可合并未合并）→ merge 修复——与
   2026-09-06 "map 分裂 ENOSPC 中间态孤儿交灾难恢复"（C 决策，§7）的工具面配套；
3. **写域显式收口**：未来 phase 层若想对某写域做确定性收敛（备选路径，非必需）。

## 2. 语义定案（已确认）

**融合对条件**（与 map_range 左并/右并同构）：

```
前.fblkbase + 前.length == 后.fblkbase                 （逻辑紧贴）
前.block_base.ptr + 前.length == 后.block_base.ptr      （物理连续）
```

满足即后记录并入前记录（左吞右），删除后记录。

**融合域（已定案）**：

- 起点：`walk(base)` 落点叶 + GLB——GLB 覆盖 base 则从 GLB 起，否则 GLB 后第一条起；
- **只向右扩出**：链式吞并向右推进，产物可越过 I 右界（起点在域内的长记录可吞域内
  后继），吞并链止于"下一条起点 ≥ base+blk_len"或树尽；**不左扩**——GLB 前一条
  （完全在 I 左）永不作为 F 的主动融合对象（M 带进来的域外记录除外，见 §4.2/§5.3）；
- **空洞 RC_OK**：I 内无记录或无可并对 → RC_OK（尽力语义，区别于 unmap 空洞的
  NOT_FOUND——那是"删除目标缺失 = 契约违反"，融合没有这种失败概念）；
- `blk_len == 0` → RC_OK 空操作（与 map/unmap 一致）。

**产物契约**（返回后树必满足，对齐现有审计）：

1. 域内无 canonical 违规残留（任意相邻记录对不满足可并条件）；
2. 非根节点 count ∈ [168, 337]，或根叶 count ∈ [0, 337]，根内部 count ∈ [2, 337]；
3. 极限产物 = 根叶单 entry（全文件融成单条记录）或空根叶；
4. 兄弟链 / 父子指针 / hint key 全套一致。

## 3. 跨度分析（为什么实现复杂度不小）

接口实际叠了三个能力，比 map/unmap 都重：

- **能力 1：叶内融合（平凡路径）**——单叶若干对可并记录，memmove + count 递减，
  无平衡无跨界，O(叶内记录数)。99% 调用命中的形态；
- **能力 2：跨界融合（游走路径）**——融合链越过叶边界：cur 末条吞 next 首条 →
  next 内部继续扫 → 再跨…… 每次跨界动兄弟链，next 可能被吞到欠载/空；
- **能力 3：坍缩式平衡（极端路径）**——刻意制造的极端：一个区间长度 1 的
  **12 万条记录全量融合**（如 120000 条 length=1、fblkbase=0..119999、phys 连续），
  融合链沿途**逐叶扫空**，树从 depth3 / ~356 叶收缩到根叶单 entry。
  打穿的机械 = 空叶欠载 → 节点合并 → 父删 hint → 父欠载上溯 → 根内部 count==1 →
  root_shrink——整条链必须全对，任何残留（空叶未 free / 欠载未修 / hint 未删 / 链断）
  即违反产物契约。

## 4. 方案演进

### 4.1 方案 A（否决）：融合游走 + 记账队列统一收敛

阶段一纯融合游走（欠载/空叶只记账、不 free），阶段二对队列逐叶 `balance_from`。
问题：

- **stale 队列**：阶段二处理叶 X 时 X 可能已被前序 balance 吞并 free——free 不擦除
  盘面，块上残留旧 meta 会误判"合法节点"继续平衡 → 灾难；每步要父链校验防 stale，
  工程复杂且难论证完备；
- 游走与平衡互相打断：balance 会把兄弟内容并进游走目标叶（记录序变化），游走指针
  语义复杂化。

### 4.2 方案 B（采纳）：F / M 双算子不动点（2026-09-06 定）

把问题重构成两个算子的不动点：

- **F（记录融合）**：节点内把可并对并掉（右扩链，域约束 I，见 §2）；
- **M（节点级合并）**：节点 count 跌破欠载线（<168）→ 不修补，把瘦节点与兄弟
  整体合一（total ≤ 337 全并、free 空侧）或抹匀（total > 337 保最低填充）→
  父删 hint → 父欠载 → **对父递归 M** → 根收缩。

伪码骨架：

```
extent_merge_range(root_blk&, owner, base, blk_len):
    walk(base) 定位起始叶 L（trace 落点）
    不动点循环:
        ① 对当前工作叶做 F：叶内顺序右扫，(i, i+1) 可并则并（左吞右），i 不动续比
           叶末跨界：cur 末 vs next 首可并 → 吞 next 首（next.count--）
           进 next 继续 ①（next 内部剩余可并对也要扫——跨界不可并不代表内部无可并）
           停：无 next / next 首起点 ≥ base+blk_len / 无可并
        ② 工作叶 count < 168 → M（现成 balance_from）：
           合并 → child 吸收邻居 → 空侧 free、父 count--、父 hint 更新
           → 父欠载 → 对父递归 M → … → 根收缩（root_blk& 带出）
        ③ **M 合并后原两叶边界出现新可并对**（child 末 vs 并进来的邻居首）
           → 回到 ① 再 F
        直到: 无 F 机会 且 无欠载 → 终
```

**方案 B 相对 A 的完备性增量**（2026-09-06 讨论中确认的关键点）：
M 合并把兄弟内容并入瘦叶后，原两叶边界处**可能相邻可并**——A 的"单向游走不回头"
会漏掉这轮新融合机会；B 的递归把"M 创造新 F 机会"显式纳入不动点，才是真正
"融到没法融"的完备语义。

**复用的现成机械**（全部已有、D/E 组 42 万次压测背书）：

- `extent_balance_from(child_blk, owner, root_blk&)`：欠载链修复（自下而上，
  父指针驱动，含收尾根收缩）；
- `extent_node_balance(parent_blk, idx, need)`：合并（total ≤ 337，保留 child
  free 邻居）或抹匀（>337，total/2 分）；
- `extent_root_shrink(root_blk&, owner)`：根内部单孩收缩；
- 跨界右吞的叶会话/链维护模式：直接镜像 `extent_map_range` 的跨界右并段。

**消灭的复杂度**：事件驱动、局部处理 → 无批处理队列、无 stale 块号问题（每次 M
的对象都是当前确认存活的节点）。

**终止性**：每轮 F 记录总数严格减少（或域尽）；M 合并节点数严格减少；M 抹匀后
两节点均回健康区、无欠载 → 无环。必停。

**与"不左扩"的边界解释（待确认，§5.3）**：F 主动扫描不左扩；但 M 是结构事件——
瘦叶向左合并会把 I 左兄弟整叶端进来，端进来后 F 按序扫描若左邻末条与本叶首条可并，
会顺带并掉 = 事实左扩。立场草案：不违反——不左扩约束的是 F 的主动扫描起点，
M 带进来的记录进了域内节点就按序处理，否则"融到没法融"不完整。

## 5. 待敲定细节（2026-09-06 遗留三个问号）

## 6. 测试设计

**铺树难点**：map 插入自动吞并可并记录 → 正常手段**铺不出**可并残留树。构造法：

- **phys-gap 分段法**（12 万条极端场景）：先 map 356 条大记录（每条 length=337，
  **phys 段间留 gap → 跨段不并**；逻辑紧贴 + phys 不连续 = 合法分离），再
  mdata_piece_session 直改叶，把每条大记录拆成 337 条 length=1 且 phys 连续的记录
  → 树 = 12 万条叶内全可并、跨段（phys gap）不可并。`merge_range` 全域 →
  预期融合到 356 条正确停点 + 沿途空叶平衡链打穿 + 树收缩；
- **小树极限产物**：单叶若干条可并记录 → 融成单叶单 entry（根叶单 entry 契约）；
- 另配：空洞 RC_OK、域右界截断（右界外起点不吞）、不左扩（GLB 前记录不动）。

**用例矩阵**：① 叶内平凡融合 ② 跨界单吞 ③ 连续多叶扫空（平衡链） ④ 12 万条
phys-gap 极端 ⑤ 融到根叶单 entry ⑥ 空洞 RC_OK ⑦ 空树（0 记录）RC_OK。

  不受此缺口影响。
